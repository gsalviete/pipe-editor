# [DOC] Amend specs for session identity and durable state (Phase 2)

## What this card solves

Phase 2 (AR-05, 06, 07, 08, 09, 23, 28) introduces concepts that no spec defines yet:
- a **document session** (the identity that says which project or document a response belongs to);
- **durable-save semantics** ("Saved" means on disk, and failures are reported and can be retried);
- **persisted provenance** (whether a saved pipeline came from detection, an import or a share link);
- **persisted-state schema validation**.

The current state spec even says persistence failures are swallowed, which is the behavior AR-07 reports as a bug.

This card drafts those amendments so TASK-007 to TASK-013 have Accepted criteria to test against. The design decisions are already made in the product doc: persist provenance, treat legacy saves as untrusted, and add minimal UI states only.
