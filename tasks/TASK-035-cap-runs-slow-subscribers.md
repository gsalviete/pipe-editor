# [FIX] Cap active runs and slow SSE subscribers (AR-25)

## What this card solves

The run registry's `maxRetainedRuns` isn't a concurrency limit: it only evicts **finished** runs, and only when a new run starts. Review probe R17 starts eight runs in a registry configured for two. Each active run copies a project and starts containers. Finished summaries stay above the limit until the next start. The SSE writer ignores `res.write()` backpressure, so a slow client's outbound queue grows without bound even though the replay buffer is bounded.

This card enforces the TASK-034 limits:
- active and queued runs are capped, and starting past the cap returns the specified refusal or queued state;
- runs are evicted as soon as they finish;
- subscriber count and retained output are bounded system-wide;
- an SSE subscriber whose buffer stays full past the threshold is closed with an explicit `stream-closed` event.
