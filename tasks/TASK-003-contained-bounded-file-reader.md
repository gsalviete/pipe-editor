# [FIX] Add a contained, bounded regular-file reader (AR-02, AR-03)

## What this card solves

Detection and discovery check that the **selected folder** is inside the workspace root. They then read `package.json`, lockfiles, `.nvmrc` and the rest by following whatever those names point to. A manifest that is a symlink to a file outside the root is read anyway (AR-02). The "bounded" reader checks `stat.size` and then calls `readFileSync`. A FIFO named `package.json` reports size 0, and reading it blocks the whole Node event loop, health and abort requests included (AR-03).

The fix is one read primitive that every manifest reader uses. It opens the file, checks that the opened file is a regular file whose real path lies inside the allowed boundary, and reads at most N bytes through the file descriptor, so a growing file can't exceed the budget. Special files are refused before any blocking read. The rejected alternative was to patch each caller with an extra `lstat`. That leaves the TOCTOU gap and keeps three copies of the rule.

The primitive also moves out of `editor-api` into a neutral module. Two core modules currently import the HTTP layer to get it, which `GUIDELINES.md` § Architecture forbids.

## Implementation plan

- New neutral module for the primitive, for example `backend/src/modules/safe-fs/` with an `index.ts` public surface (`GUIDELINES.md` § Code style). Name it to match kebab-case module naming. It exports `readContainedFile(path, { boundary, maxBytes })` and the existing `ManifestTooLargeError`/`MAX_MANIFEST_BYTES` (currently `editor-api/bounded-read.ts:15-29`).
- Algorithm: `openSync(path, O_RDONLY | O_NOFOLLOW*)` (the flag depends on the TASK-001 policy), then `fstatSync(fd)` and require `isFile()`, then `realpathSync(path)` and check containment against the boundary (reuse the containment helper style of `editor-api/path-security.ts`), then read in chunks until `maxBytes + 1`.
- Replace callers:
  - `detector/manifests.ts:16,36-47`: import from the new module and drop the `existsSync` + `statSync().isFile()` pre-check. The primitive now owns it, and `readManifests` must receive the boundary.
  - `editor-api/project-scan.ts:10,214`: `probeProject` reads through the primitive with the workspace root as its boundary.
  - `workspace-bundle/inspect.ts:3,43,194`: same, and removes the second `editor-api` import.
- Leave `editor-api/bounded-read.ts` as a thin re-export only if other importers remain. Otherwise delete it and update its spec test file.
- Keep DET-FR-019: an unreadable `package.json` still raises `MalformedPackageJsonError` (`detector/manifests.ts:49-50`), and the other manifests still warn and skip.
- Validation: `pnpm --dir backend test`, then `pnpm check`.
- Size: ~180 production lines.
- Out of scope: `findCiConfigs` and the import controller reader (TASK-004), and moving scanning off the synchronous path (a §7 follow-up).

## Attention points

- Security (Critical per `GUIDELINES.md` § Domain criticality): the check must be on the file **actually opened** (fd-based), not on a path checked earlier.
- Removing the `existsSync` pre-check changes error types. A missing manifest must stay "absent", not become an error, so map `ENOENT` explicitly.
- Nested `node_modules` in pnpm projects are symlink-heavy. The detector only reads top-level manifests, so the primitive must not be used for the copy (EXEC-FR-007).
- ❌ Don't add a synchronous `readFileSync` fallback "for small files". The byte budget applies to every read.
- Rollback: the change is internal to readers. Reverting restores the previous (vulnerable) behavior with no data impact.

## Observability

- Skipped or rejected manifests surface as detector warnings and scan diagnostics (user-visible). Don't log to the console beyond `console.warn` for unexpected fs errors, and include no file contents (`GUIDELINES.md` § Logging).
