# [DOC] Amend specs for filesystem containment (Phase 1)

## What this card solves

Phase 1 of Hardening v2 (AR-01 to AR-04) changes behavior that the current specs either don't cover or describe too loosely. `CLAUDE.md` forbids implementation without an Accepted spec, so this card writes the amendments that TASK-002 to TASK-005 implement against.

The review showed three boundary gaps: the executor's visibility marker is written through symlinks (AR-01), manifest reads follow file symlinks out of the workspace (AR-02), and the "bounded" reader blocks on FIFOs (AR-03). It also showed a gate gap: nothing proves the production images build (AR-04). Each needs a verifiable requirement and acceptance criterion with a stable ID so the fix cards can name their tests after them.

This card also settles the product doc's first open question: the policy for symlinks that stay **inside** the workspace (follow, skip or reject).
