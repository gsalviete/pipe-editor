# [FIX] Keep per-step context in GitHub and GitLab exports (AR-12)

## What this card solves

The single-service CI exporters flatten a stage into one `run:` block (GitHub) or one job `script:` (GitLab), with the env of every step merged and no working directory at all. A pipeline imported from GitHub Actions, where each step has its own `env:` and `working-directory:`, therefore exports back into something with different meaning (review probe R06, the export half: "the GitHub output contains no directory configuration").

This card makes each IR step keep its env and directory in the exports.
- **GitHub Actions:** each IR step becomes its own workflow step with `env:` and `working-directory:`, since GHA supports both natively.
- **GitLab:** jobs have no per-step env, so each script entry is wrapped in a subshell with the step's `cd` and env. It uses the same construction as TASK-021, so local runs and GitLab agree.
