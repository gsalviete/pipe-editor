# [FIX] Serialize autosave and show honest save state (AR-07, AR-08)

## What this card solves

Autosave fires a `PUT` (or a `DELETE` when the document is back to pristine) after a debounce, but requests carry no revision and aren't ordered. If the user edits and then undoes to the baseline while the first `PUT` is in flight, `savedThisSession` is still false, so no `DELETE` is scheduled. The old `PUT` then resolves, shows "Saved", and leaves the edit on disk while the UI is pristine (review probe U03). Old completions can also change the shared flag after a project switch. Separately, the indicator can't show a failure, even now that TASK-008 reports one.

The fix gives saves a per-project queue with a monotonically increasing revision. Only the latest intended state is written once in-flight requests settle, and completions from an older revision or another project are ignored. The indicator gets an honest third state, "Not saved — retry". The rejected alternative was cancelling requests with `AbortController`. An aborted `fetch` may already have reached the server, so cancelling doesn't guarantee what ends up on disk.
