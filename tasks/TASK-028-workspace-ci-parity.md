# [FIX] Bring workspace CI to parity with single export (AR-18)

## What this card solves

A Workspace Bundle generates CI for several services through a separate, weaker translation path than the single-service exporters:
- it copies `step.run` but drops `step.env` and per-step directories;
- GitHub runs on the VM with setup-node and ignores stage images;
- GitLab picks only the first verification stage's image;
- the GitHub workflow hardcodes `branches: [main]` whatever the triggers say.

Unlike single export, none of this is reported, and the bundle's own check only looks for string presence.

This card routes the workspace generators through the shared translation rules from Phase 3 and 4 (per-step context, job namespace, trigger rules, artifact handoff). Where the multi-service layout genuinely differs (one job per service), the header reports each difference explicitly.
