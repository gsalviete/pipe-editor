# [FIX] Validate persisted state and use prototype-safe keys (AR-23)

## What this card solves

The state store trusts whatever `JSON.parse` returns from `pipelines.json` and `runs.json`. A file that contains `[]`, `42` or `{ "app": null }` leads to silent non-persistence or a crash outside the parse `catch`. Saved IRs come back without `validate()`. The pipelines map is a plain object, so a legal directory named `__proto__` or `constructor` hits the prototype: review probe R12 shows a save for `__proto__` vanishing from the persisted keys.

The fix validates each file's shape on load and keeps healthy records while dropping malformed ones. It runs `validate()` on each saved IR and stores pipelines in a null-prototype map with own-property access only. The rejected alternative was to wipe a file that fails validation. That loses healthy records, which the product doc forbids.

## Implementation plan

- `backend/src/modules/state-store/store.ts`:
  - `:44` `pipelines: Record<string, SavedPipeline> | null` becomes a `Map<string, SavedPipeline>` (or `Object.create(null)` with `Object.hasOwn`). `getPipeline` (`:54-56`), `deletePipeline` (`:70-76`) and `listPipelines` (`:79-85`) use own-property access only.
  - `:102-115` `loadPipelines`/`loadRuns`: after `read`, validate per record. A record needs a string `projectPath`, a string `savedAt`, and an `ir` for which `validate(ir).length === 0` (import `validate` from `../ir`, which is allowed per `GUIDELINES.md` § Architecture). Drop invalid records and keep the rest.
  - `:117-124` `read<T>`: keep the missing/corrupt fallback, but never cast unknown shapes to `T`.
  - Serialize the Map back to a plain JSON object on write, so the on-disk format doesn't change.
- Validation: `pnpm --dir backend test -- store`, then `pnpm check`.
