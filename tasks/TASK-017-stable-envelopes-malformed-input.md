# [FIX] Return stable envelopes for malformed boundary input (AR-30)

## What this card solves

Several inputs get past loose checks and turn into internal errors instead of actionable 4xx envelopes:
- a `package.json` that is JSON `null` parses fine, then crashes property access during scan (review probe R13);
- GitHub `jobs: null`, or null job and step entries, pass the `typeof === 'object'` checks in the importer;
- bad JSON bodies, oversized bodies and unknown routes return Nest/Express defaults, not the project's `{ error: { code, message, detail? } }` envelope.

The global `ValidationPipe` gives false confidence, because the handlers take untyped bodies with no DTO schema.

This card makes every boundary narrow its input from `unknown` before use, and adds one exception filter that maps body-parser errors and 404s to the envelope. `GUIDELINES.md` § Error handling requires that no raw 500 reaches the client.

## Implementation plan

- `backend/src/modules/editor-api/project-scan.ts:205-231` `probeProject`: after `JSON.parse`, require a non-null object before reading `name`/`scripts`/`packageManager`/`workspaces`, and treat anything else like a malformed manifest (listed, with the basename as its name).
- `backend/src/modules/ci-import/github-actions.ts:40-43`: require `jobs` to be a non-null, non-array object, and each job and step entry to be one too (`:98`, `:102`). Throw `CiImportError` with a specific message.
- Apply the same narrowing in `ci-import/gitlab-ci.ts` for job entries.
- New `editor-api/http-exception.filter.ts`: a `@Catch()` filter that maps body-parser `entity.parse.failed` and `entity.too.large` errors, and route 404s, to `envelope()` from `http-errors.ts`. Register it in `main.ts` (`:21-50`), and add any new code to the `ErrorCode` union first (spec-first).
- Validation: `pnpm --dir backend test`, then `pnpm check`.
- Size: ~150 production lines.
- Out of scope: IR field validation (TASK-015).

## Attention points

- The filter must not swallow the envelopes that controllers already throw (`HttpException` carrying an envelope). Pass those through unchanged.
- Wire contracts: `editor-api/wire-contracts.spec.ts` pins response shapes. Extend it, and don't loosen it.
- ❌ Don't add DTO classes with class-validator just to satisfy the pipe. Explicit narrowing is the pattern here (`state.controller.ts:54-60`).

## Observability

- `console.error` in the filter only for genuinely unmapped exceptions (the programmer-fault path), with the error name and message and no request body (`GUIDELINES.md` § Logging).
