# [FIX] Reset studio on rescan; drop stale bundles (AR-06, AR-09)

## What this card solves

Two stale-state bugs in the workspace studio:
- **AR-06:** the studio copies its `initialPlan` prop into state only once, when it mounts. Scanning another folder while the studio is open passes a new plan that is ignored, so the user keeps editing and generating the old workspace's services (review probe U01).
- **AR-09:** an edit clears the current bundle, but a generation request already in flight reinstalls its outdated artifacts when it returns. The user sees OLD ARTIFACT next to the new command (review probe U02).

The fixes: remount the studio per scanned workspace (key it by a scan id, so unrelated re-renders keep edits), and tag every generate request with a revision of `(plan, provider, composeMode)`. A response whose revision no longer matches is dropped or marked stale, whichever TASK-006 specifies.
