# [FIX] Prefer explicit runtime evidence over fallback images (AR-22)

## What this card solves

A GitHub job that runs on a VM with `actions/setup-node` set to `node-version: 22` and no container is assigned the fallback image `node:20-alpine`. Inference then reads the runtime version **from that invented image** before it looks at the setup-node hint, so the import reports runtime 20 and image 20 (review probe R15). The generic fallback warning doesn't say that explicit evidence was discarded.

The fix: the importer records whether each image was **observed** or a **fallback**. Inference considers observed images first, then setup-node hints, and only then fallbacks. The fallback image is chosen to match the explicit runtime (`node:22-alpine`), and conflicts between hints are reported by name.
