# [DOC] Amend specs for validation and execution agreement (Phase 3)

## What this card solves

In Phase 3 (AR-10, 11, 12, 13, 14, 24, 30), the review found the **specs themselves** wrong in places, not just the code:
- **EXEC-FR-008** explicitly merges every step's env into one container env. The product doc decided per-step context is kept everywhere, so FR-008 is superseded.
- **EXEC-FR-009/010** describe one working directory per stage and a ` && ` join, while the code already joins with newlines under `set -e` (IMP-01). The spec is out of date.
- The IR spec leaves `triggers` unvalidated, requires only a non-null `metadata`, has no supported-version policy, and bounds depth but not total size.
- The Dockerfile spec has no encoding for multi-line scripts.

This card drafts those amendments and settles three open questions from the product doc: the multi-line encoding, the version policy, and the IR size budgets.
