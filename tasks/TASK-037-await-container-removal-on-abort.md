# [FIX] Await confirmed container removal on abort (AR-26)

## What this card solves

Abort is best-effort today. If the cidfile exists, a detached `docker stop` is started, and then the CLI client is killed. An abort that arrives before Docker writes the cidfile stops nothing. Workspace cleanup can delete the copy while the container is still running against it. The visibility probe ignores the abort signal. Errors from the detached stop process are emitted asynchronously, so the surrounding synchronous `try/catch` never sees them.

The review is explicit that this is a code-path finding, not a demonstrated escape. The fix makes the lifecycle deterministic:
- containers are started with a known name, so abort can target them even before the cidfile exists;
- stop and removal are awaited, with confirmation, before workspace cleanup;
- the probe honors the signal;
- every child process has an `error` handler.

## Implementation plan

- `backend/src/modules/executor/docker-client.ts`:
  - The stage run uses `docker run --name pipe-editor-<runId>-<stageId>` (plus the existing `--rm`/cidfile).
  - `onAbort` (`:153-163`) calls an async `removeContainer(name)` that runs `docker rm -f` and awaits its exit, with an `error` handler.
  - Replace `stopContainer` (`:203-219`) with it.
  - The promise from `runStageInContainer` settles only after removal is confirmed or has definitively failed; report a failure in `stderr`.
- `backend/src/modules/executor/workspace-visibility.ts`: `assertWorkspaceVisible` accepts `signal`, and `runProbe` names and removes its container the same way.
- `backend/src/modules/executor/execute.ts:97-102,164-165`: pass the signal to the probe, and call `workspace.cleanup()` only after the stage promise settles.
- Validation: `pnpm --dir backend test -- executor`, then `pnpm check`.
- Size: ~120 production lines.

## Attention points

- Container names must be unique per run and stage, and valid Docker names. Reuse the `docker-naming` helpers.
- `docker rm -f` on a container that `--rm` already removed returns non-zero with "No such container". Treat that as success.
- ❌ Don't add stage timeouts here. They are a non-goal (TASK-034).

## Observability

- `console.warn` when container removal cannot be confirmed (container name and docker exit code only).
