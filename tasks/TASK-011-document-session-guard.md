# [FIX] Guard editor responses with a document session (AR-05, AR-23)

## What this card solves

After detecting project A, the editor asks for A's saved pipeline without tying the request to A. If the user detects project B before that answer arrives, A's saved pipeline becomes B's restore candidate. Restoring it applies A's IR under B: autosave then writes it as B's pipeline, and a run executes it against B's files (review probe U04). The restore also applies the IR without running `validate()`.

This card introduces a **document session**: an id that is created whenever a new document is loaded (detect, import, share link, folder bind). Every async response checks it before touching state, and restore requires the saved record's project identity to match the current project and the IR to pass `validate()`. The rejected alternative was a per-request `AbortController`. It doesn't cover responses that have already resolved and are waiting in a `.then`.
