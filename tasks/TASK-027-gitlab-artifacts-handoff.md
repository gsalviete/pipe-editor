# [FIX] Hand GitLab outputs through artifacts, not cache (AR-17)

## What this card solves

Exported GitLab jobs assume `node_modules/` and `dist/` arrive from earlier jobs through a cache keyed only by the lockfile. GitLab caches are best-effort: another runner can miss them, and a different pipeline with the same lockfile can reuse them. The header even calls the cache "pipeline-scoped", but its key has no pipeline identity. Files that custom stages create aren't transferred at all.

The product doc decided on **artifacts + `needs`**. Outputs pass from the current pipeline through `artifacts` + `needs`, the cache only speeds up dependency installs, and every job can reinstall from an empty cache. That's the layout GitLab's own docs recommend for intermediate build results.
