# [FIX] Restore provenance and bind review to the document (AR-28)

## What this card solves

This is the frontend half of AR-28. Detect sets provenance to `detected`, and restoring a saved imported pipeline doesn't change that, so the run skips the untrusted-command review. The run panel also resets the acknowledgement only when the provenance kind or label changes. Two different imports that share a file name therefore count as already reviewed. The review dialog lists command text but not the image, env or directory, which also affect what runs.

With TASK-009 persisting provenance, this card:
- restores provenance together with the IR;
- saves it on every autosave;
- ties the acknowledgement to the document session (TASK-011) plus a digest of the execution context (commands, images, env, working directories);
- shows that context in the review.

Any change to the context requires a fresh review.
