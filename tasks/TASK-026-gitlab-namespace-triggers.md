# [FIX] Namespace GitLab jobs and honor trigger branches (AR-15, AR-16)

## What this card solves

Two GitLab export bugs:
- **AR-15:** the exporter writes the `stages` list and then assigns each job to `doc[stage.id]`. A valid IR stage named `stages` replaces the list with a job object (review probe R08). Names like `image`, `default`, `variables`, `cache`, `workflow` or `include` are read as global keywords.
- **AR-16:** changing the trigger branches in the editor changes the GitHub export, but the GitLab export stays byte-identical (review probe R16). No `rules`/`workflow` filter is emitted.

The fix gives jobs a namespace that can't collide with keywords, whatever the IR ids are (as TASK-024 specifies, for example a fixed prefix plus the IR id), with the stage and dependency mappings kept intact. It also emits a `workflow: rules:` filter for the trigger branches and pipeline source, and warns or refuses for anything that can't be expressed, per TASK-024.
