# [FIX] Canonical run/export order; refuse empty runs (AR-13, AR-14)

## What this card solves

**AR-13:** `validate()` accepts a linear dependency chain whatever the order of the `stages` array, and `canonicalize()` knows the right order. `computeEffectiveChain()` keeps the incoming array order, though, and the executor iterates the raw array. `[second dependsOn first, first]` validates and runs `echo SECOND` before `echo FIRST` (review probe R05). Exporting canonical JSON and re-importing it changes behavior.

**AR-14:** the empty-chain refusal is guarded by `stages.length > 0`, so a fully resolved IR with `stages: []` goes through the Docker check, the workspace copy and the probe, runs nothing, and reports **passed** (R07).

The fix: `computeEffectiveChain` returns stages in canonical topological order. It's the single shared transform (IR-FR-014), so the executor, both CI exporters, the Dockerfile generator and the workspace bundle all inherit the order. The executor iterates that order for both results and execution. A zero-stage document returns a no-work result before any Docker or filesystem work.
