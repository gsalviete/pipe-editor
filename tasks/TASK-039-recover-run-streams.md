# [FIX] Recover lost run streams without duplicated output (AR-27)

## What this card solves

The run panel depends on `EventSource`'s automatic reconnect and reports a loss only when the stream reaches `CLOSED`. It has these gaps:
- events have no ids, so a reconnect replays the buffered log and the user sees output twice;
- there is no fallback to the run summary endpoint;
- the backend's `stream-closed` event (eviction, and after TASK-035 the slow-client drop) isn't handled;
- runs that were evicted or lost to a backend restart can stay "running" in the UI forever;
- opening a past run from history closes the live stream and drops the Abort control of the run that is still active.

This card adds SSE event ids (the backend sends `id:` and honors `Last-Event-ID`), handles `stream-closed`, reconciles with the summary endpoint after loss or eviction, and keeps the active run observable and abortable while the user views history.

## Implementation plan

- Backend `backend/src/modules/editor-api/run-registry.ts`: give each pushed event a sequence number, and let `subscribe(id, listener, afterSeq?)` replay only newer events (`:162-168`).
- `backend/src/modules/editor-api/execute.controller.ts:184-186`: write `id: <seq>\n` before `data:`, and read `req.headers['last-event-id']`.
- Frontend `frontend/src/editor/api.ts:370-396` `openRunStream`:
  - track the last applied event id and drop frames at or below it;
  - handle `stream-closed` (call a new `onClosed(reason)`);
  - on `CLOSED` or `stream-closed`, fetch the summary (the existing summary API in `api.ts`) and deliver its terminal result.
- `frontend/src/editor/RunPanel.tsx:231-248` `loadPastRun`: don't close the active stream. Keep the live run in separate state and show history in a secondary view, with a control to return to the live run.
- Validation: `pnpm --dir backend test -- run-registry execute`, `pnpm --dir frontend test`, then `pnpm check`.
- Size: ~180 production lines.

## Attention points

- The SSE replay buffer drops `stage-output` beyond `MAX_REPLAYABLE_OUTPUT_CHARS` (`run-registry.ts:65`). Sequence numbers must stay consistent when output is truncated (the ids of skipped frames are simply absent).
- `RunPanel.tsx` is 590 lines. If this card pushes it past about 400 lines of new logic, extract a `useRunStream` hook (`GUIDELINES.md` § Frontend: keep components focused).
- ❌ Don't replace SSE with polling. Polling is only the reconciliation fallback.
