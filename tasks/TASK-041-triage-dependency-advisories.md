# [DX] Triage dependency advisories and upgrade safely (AR-29)

## What this card solves

`pnpm audit` reports advisories in the locked trees:
- backend: 31 high overall, 10 high in production;
- frontend: 1 critical (Vitest's UI server, dev-only) and 9 high in dev, with production clean.

Registry counts aren't proof that anything is exploitable. The backend has no upload route, for example, so the multer advisories may be unreachable. Nobody has triaged them either.

This card triages each advisory by installed version, dependency path and reachable feature, as TASK-040's policy says. Compatible parent and toolchain upgrades ship as their own change, and each advisory that remains gets a recorded, justified exception. Blanket forced major upgrades are ruled out by the product doc.

## Test criteria

The gate is the real toolchain:

```sh
# it('every advisory is either resolved or has a recorded exception')
pnpm --dir backend audit --json   # compare against the exceptions record → no unlisted advisory
pnpm --dir frontend audit --json
# it('frozen installs, full gate and images still pass after upgrades')
pnpm --dir backend install --frozen-lockfile && pnpm --dir frontend install --frozen-lockfile
pnpm check
docker build -f backend/Dockerfile . && docker build -f frontend/Dockerfile .
```

- Keep direct `js-yaml` 4.x separate from older transitive instances, as the review warns (ARCH-02: one direct version across both packages).

## Implementation plan

- Start from `docs/reports/review-evidence/dependency-audit.json`, then re-run the audits on the current tree.
- For each advisory, record the package, installed version, path (`pnpm why <pkg>`), whether it's reachable (feature used or not), and the action (upgrade the parent, override, or accept with a reason). Put the records in the exceptions file TASK-040 defines.
- Upgrades: **ask the owner before each dependency change**, giving the name and target version (Layer 1). Prefer minor or patch upgrades of the direct parents. Use `pnpm.overrides` only with a justification line.
- Lockfile changes don't count toward the 500-line budget (`docs/agents/validation.md`).
- Validation: the commands above.
- Out of scope: test-boundary fixes (TASK-042), and new features.

## Attention points

- Nest major upgrades can break decorators and Swagger. If a fix needs a major, record it as an exception with a follow-up rather than forcing it.
- The Vitest critical affects `vitest --ui` only (a listening server). Check whether `@vitest/ui` is ever started in scripts or CI (`frontend/package.json` `test:watch` doesn't start it). Record reachability.
- ❌ Don't install from a custom registry or run `curl | sh` installers (Layer 1).
