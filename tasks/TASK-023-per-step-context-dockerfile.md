# [FIX] Keep per-step context in Dockerfile builds (AR-12)

## What this card solves

The Dockerfile generators emit the install and build steps with no working directory and no env, so a build step meant to run in `packages/api` with `NODE_ENV=production` runs at `/app` with neither. This is the last consumer of AR-12's per-step context.

On top of TASK-019's multi-line encoding, each step's script runs in its own subshell with its directory and env, using the TASK-021 construction. The generated Dockerfile then builds the same way the local run executes.

## Test criteria

Backend (Jest) plus a **real Docker build**. Use the DOCKER-AC IDs from TASK-014.

```ts
describe('T-DOCKER-### (DOCKER-AC-### AR-12) — per-step context in RUN', () => {
  it('a build step with workingDir "one" and env MODE=one writes one/out = "one" inside the image')
    // Act: generate → docker build → docker run --rm img cat /app/one/out
    // Assert: stdout.trim() === 'one'
  it('two build steps with different contexts both take effect')
  it('a Vite service build step keeps its context too (workspace-bundle template)')
})
```

## Implementation plan

- `backend/src/modules/dockerfile-generator/generate.ts:285-343` (install and build rendering): feed the TASK-019 encoder with the per-step construction from TASK-021's shared helper.
- `backend/src/modules/workspace-bundle/generate.ts:146`: the Vite build uses the same helper.
- Env values in a Dockerfile are part of the committed artifact. Only emit env the IR step carries, and add a header note that step env is baked into image layers.
- Validation: `pnpm --dir backend test -- dockerfile-generator workspace-bundle`, the `images:` gate, then `pnpm check`.
- Size: ~80 production lines.

## Attention points

- Secrets: env values end up in the Dockerfile and in image history. The header must warn about this (honest claims). ❌ Don't silently drop env to avoid the issue; that is the AR-12 bug.
- Golden Dockerfiles for fixtures whose steps have no env and default directories must stay unchanged.
- If TASK-019 is still using ` && ` in any path, stop and reconcile first.
