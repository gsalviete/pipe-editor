# [FIX] Generate a Vite Dockerfile that works without a lockfile (AR-19)

## What this card solves

Detection already switches a project with no lockfile to a resolving install (`npm install` rather than `npm ci`); that was the earlier GEN-04 fix. The Vite template in the workspace generator never got that fix. It always emits `COPY package.json package-lock.json ./` and a frozen install, so a Vite service without a lockfile gets a Dockerfile that can't build (review probe R11).

This card makes the Vite template use the install stage's actual commands and copy the lockfile only when one exists. When no honest buildable artifact is possible, the generator returns the explicit unsupported response TASK-024 specifies. Install rendering moves to one shared function, so the templates can't drift apart again.

## Implementation plan

- `backend/src/modules/workspace-bundle/generate.ts:155-156`: take the install command from the service IR's effective `install` stage (as the single-service generator does), and emit the lockfile `COPY` only if the detected facts say a lockfile exists. `lockfileFor` is at `:415-419`, `installCommand` is in this file.
- Share install rendering with `dockerfile-generator/generate.ts` (install text at `:285-291`) through its public `index.ts`.
- New fixture `test/fixtures/vite-no-lockfile/` with a README line saying it is synthetic (the fixtures convention in `docs/testing/test-strategy.md` § Fixtures).
- Validation: `pnpm --dir backend test -- workspace-bundle`, the `images:` gate, then `pnpm check`.
- Size: ~60 production lines.

## Attention points

- Workspace fixtures currently write `{}` as lockfiles (review AR-31). The new fixture must be a real, installable Vite app, or the build test proves nothing.
- A Docker build downloads npm packages, so it needs network in the test environment. Mark the test like the existing Docker suites and document it.
- ❌ Don't generate a lockfile inside the Dockerfile to "fix" the frozen install. It hides the missing-lockfile state from the user.
