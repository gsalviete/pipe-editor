# [FIX] Persist provenance with saved pipelines (AR-28)

## What this card solves

The editor asks the user to review commands before running a pipeline that came from an import or a share link, because those commands weren't authored or detected locally. The store saves only the IR, though. After a reload, a restored imported pipeline looks like a detected one, and the next run skips the review.

This card makes provenance part of the saved record. `PUT /api/state/pipeline` accepts and stores it, and `GET` returns it. A record saved before this change, with no provenance, is returned as untrusted (the product doc's decision). The frontend use of this field is TASK-012.

## Implementation plan

- `backend/src/modules/state-store/store.ts:19-23`: add `provenance` to `SavedPipeline`, shaped as TASK-006 specifies (the kind plus an optional label or identity). Extend the TASK-007 record validation to accept a missing provenance and map it to the legacy-untrusted value.
- `backend/src/modules/editor-api/state.controller.ts:53-66`: read and validate `body.provenance`, and pass it to `savePipeline`.
- Frontend type mirror: `IRProvenance` is imported in `frontend/src/editor/Editor.tsx:51`. The wire type in `frontend/src/editor/api.ts` (`getSavedPipeline`/`putSavedPipeline`) gains the field. It's optional on read, so this card can land before TASK-012.
- Wire contracts: update `editor-api/wire-contracts.spec.ts` for the new field.
- Validation: `pnpm --dir backend test -- store state wire-contracts`, then `pnpm check`.
- Size: ~70 production lines.
- Out of scope: frontend restore and acknowledgement binding (TASK-012).

## Attention points

- Security: High. Losing provenance bypasses the untrusted-command review.
- Backward compatibility: existing saves have no provenance. They must load as **untrusted**, never as `detected`.
- ❌ Don't derive provenance from the IR's `metadata.detectorVersion`. It is client-supplied and not an identity.

## Observability

No new observability requirements — provenance is surfaced to the user through the existing run-review flow.
