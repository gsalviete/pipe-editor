# [FIX] Bound validation work on aliased or cyclic input (AR-24)

## What this card solves

`js-yaml` can build object graphs with shared aliases and even cycles. The validator's recursive forbidden-key walk caps depth, but it revisits shared nodes, piles up duplicate errors, and blows the stack on a cycle. `metadata: &x [*x, *x]` produces `RangeError: Maximum call stack size exceeded` (review probe L01). In the browser, validating an imported YAML happens outside the parse `catch`, so this becomes an unhandled error. File import also reads arbitrarily large files in full before validating.

The fix tracks visited objects (so cycles are rejected and shared nodes are walked once) and bounds the total node count, error count, string length and input bytes to the numbers TASK-014 sets. Invalid input then produces a recoverable error with bounded work.

## Implementation plan

- `backend/src/modules/ir/validate.ts:69-103` `validateForbiddenKeys`: add a `visited: WeakSet<object>` and a shared `budget` counter object. Return an IR-AC error on a revisited object on the current path (a cycle), skip already-validated shared nodes, and stop when the budget is exhausted.
- `validate()` (`:55-62`): cap the errors array at MAX_ERRORS.
- `frontend/src/editor/Editor.tsx:574-606` `loadExternalIR`: wrap `validate(parsed)` (`:596`) in the same try/catch that reports through `setDetectError`, and check `text.length` against the input budget before parsing. The drop and file-picker paths check `file.size` before `file.text()`.
- Validation: `pnpm --dir backend test -- ir`, `pnpm --dir frontend test`, then `pnpm check`.
- Size: ~100 production lines.
- Out of scope: HTTP body limits (TASK-017; `main.ts:25` already sets `json({ limit: '1mb' })`).

## Attention points

- The frontend imports the same validator through `@modules/ir`. Keep it free of Node APIs (`WeakSet` is fine).
- `js-yaml` `load` itself can expand aliases (a billion-laughs style attack). Check whether the installed js-yaml version limits alias expansion, and note the result in the card handoff.
- ❌ Don't raise `MAX_DOCUMENT_DEPTH` or remove it. Depth and node bounds are complementary.
