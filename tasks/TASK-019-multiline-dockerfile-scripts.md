# [FIX] Encode multi-line scripts safely in Dockerfiles (AR-11)

## What this card solves

Build steps are joined with ` && ` and emitted as a single `RUN` line. A step containing `echo first\necho second` becomes `RUN echo first` followed by the line `echo second`, which isn't a valid Dockerfile instruction (review probe R04). A trailing `# comment` in one step swallows the ` && ` and every later step. Imported GitHub Actions `run: |` blocks are multi-line by nature, so this breaks exactly the pipelines the import feature brings in.

The executor and the CI exporters already fixed this (IMP-01: newline-joined under `set -e`). This card brings the Dockerfile generators to the same semantics using the encoding TASK-014 chose (heredoc `RUN` or a generated script). Ad-hoc newline escaping is rejected, as the review requires.
